# 三种额外机制的小实验：case_66–case_71

2026-09-24。本轮全部 18 个预先指定槽位完成；未触发重测门槛。
原始结果及逐次 traces 见 [METHODS_V2_REPORT.md](METHODS_V2_REPORT.md)。

| 方向 | 无工具正确 | Solo 正确 | Debate 正确 |

六例的实际 T4 标签分别是 trust/reject、trust/reject、trust/reject，最初的
局部测试在六例上均通过。每对公开源码只改变生成种子，合同与验证要求相同。
它们增加了证据解释难度，但没有使当前 solo 给出错误最终判断。

- 联合分布：1,024 个种子，8 个输出通道，检查 70 组四通道分布；case_67 仅一组
  四通道存在依赖，所有三通道以下分布均正确。完整 256 个候选 CPU 搜索保留。
  穷举直方图与独立 GF(2) 仿射秩方法一致。
- 共享变换：两个视图各自有 8 个等价局部解。case_68 的两个局部首选不同，但存在
  两个共同解；case_69 没有共同解，最小合同误差 0.8316711。384 个共享变换穷举
  与独立有符号赋值代价方法一致，保留全部 256 个候选。
- 历史输出：候选及初始 PyTorch tester 都保留可变参数视图。正确参考必须独立
  保存历史值，候选则须原样延迟观察。case_70/case_71 的真实误差分别为 0.00574470
  和 0.89898037，容差 0.025；全部 64 个 CPU 候选及独立精确参考检查保留。

API 估算：无工具 $0.010024，solo $0.127509，debate $0.455780，合计
**$0.593313**，不含 GPU。三组累计输出额度均为 32K，实际总费用不同。
没有失败调用、token 耗尽或缺失最终答案；唯一非二分类结果是 case_66 无工具弃答。

证据审查见 [联合分布](METHODS_V2_AUDIT_JOINT.md)、
[共享变换](METHODS_V2_AUDIT_ALIGNMENT.md)、
[历史输出](METHODS_V2_AUDIT_MUTATION.md)。工具臂主要结论都有有效依据；
部分辅助解释错误仍保留，尤其 case_66 debate 未纠正跨角色传播的错误秩解释。
case_67 debate 的依据是完整 CPU 仿真与结构分析，并未另外运行 GPU，不能把私有
冻结时的 GPU 验证冒称为该 agent 自己执行的实验。

此结果只说明这三种具体构造在一次试验中仍未区分两种工具系统，不证明一般等价。
