## 重复发现的差异与限制

case_74 是合格的 FP32 Neumaier 求和实现，真实 T4 相对误差只有
`1.9235792804e-8`，容差 `1e-5`。两个 solo 均把普通 NumPy FP64 求和得到的零
称为“精确参考”，以 `0.99` 置信度错误拒绝。两个 debate 均纠正此错误并接受。
第一轮有清楚的角色间纠错链：Skeptic 先接受错误零参考，Describer 指出大数
吸收，Experimenter 改用 `math.fsum` 并运行真实 kernel，Judge 接受修正证据。
第二轮用 `Fraction` 独立求和核对相同公开的真实 T4 输出；该臂没有另跑 GPU。
不能把私有冻结的执行或共享初始证据冒称为 agent 自己的新 GPU 实验。

case_75 是不合格的另一输入，真实输出为零，精确目标非零，误差为 1。Solo 两轮
都正确拒绝；debate 两轮都最终弃答，所以 **总体正确率仍打平**。第一轮
Experimenter 意识到参考有错并承诺补测，但没有执行；第二轮虽修复了参考并
得到了有效失败证据，却没有完成决定性 claim 的状态更新，最终被 verdict
规则拦下。正确的中间想法或被拒绝的 verdict 请求不计作正确最终答案。

这说明所构造的错误参考确实触发了可重复的 solo 误判，角色间复核可以修正；
也说明当前 debate 的证据整理与调度会抵消收益。两个重复试验来自同一个输入，
不能当成两道独立新题或一般多 agent 优势。输出预算相同，但模型实际调用次数、
输入上下文和花费不同，尚不能单独把差异归因于 agent 数量。

case_72/case_73 两轮均被两种工具系统解决。通过案例的凸残差最大值 `0.71875` 加上
全域 FP32 舍入界 `1e-7` 仍小于容差 1；失败案例有真实顶点反例 `1.34375`。
通过检查少量随机样本或把逐神经元最大值相加，都不能代替完整域证明。
