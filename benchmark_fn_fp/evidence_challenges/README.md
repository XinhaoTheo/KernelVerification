## 四个初始案例

| 案例 | 机制 | 初始实验 | 独立 T4 真值 |
|---|---|---|---|
| case_62 | FP32 原始矩协方差 → 岭回归 → 查询预测；tester 共用相同不稳定代数 | 通过，误差 0 | 合格；真实相对误差 0.00206523 ≤ 0.05 |
| case_63 | 与 case_62 相同，只有输入 seed 不同 | 通过，误差 0 | 不合格；真实相对误差 0.25584796 > 0.05 |
| case_64 | 缓存重排与追加；初始 tester 只测试五个短操作字 | 五项全通过 | 合格；全部 121 个合法操作字误差 0 |
| case_65 | 与 case_64 相同，只有输入 seed 不同 | 五项全通过 | 不合格；12/121 个操作字失败，最大绝对误差 7.625 |

两种初始测试的输出都来自真实 T4 执行，并在首次模型调用前写入公开合同。
它们不是 ground-truth 标签。三个实验组得到相同公开源代码、合同与初始结果。
case_64/case_65 的完整有限输入域直接写在合同中；不存在用隐藏的输入范围判错。

case_62/case_63 使用 FP64 居中增广最小二乘与 80 位 Decimal 独立求解作为两套参考。
完整 256-seed 搜索中 166 个数值合格，选择最小/最大误差；没有使用模型反馈。
case_64/case_65 使用 FP64 正向逻辑状态与整数反向祖先追踪，64 seeds × 121 个操作字
全部检查，两参考严格一致；17 个 seed 完全合格、47 个有违反，选择首个满足条件
的合格/不合格 seed。两类均重复实际 GPU 的决定性工作负载十次。

## 实验规则

见首次模型调用前写定的 [PROTOCOL.md](PROTOCOL.md)。先运行四例 × 三组的一轮。
只有出现明确的 solo 错、debate 对，才为全部四例做第二轮；同一案例复现并完成
证据审查后，才按冻结规则新增六例，构成约十例。未通过这个门槛则停止付费扩量。

每组每次运行总输出 token 上限为 32768（包含推理 token）。多角色共享额度，
并非每个角色各有一份。这个限制没有匹配输入 token、费用或 GPU 时间，因此不能
直接宣称是完全同成本比较。两种工具组使用原有提示和流程，尚未升级角色行为。

[REPORT.md](REPORT.md) 和 private_data/reports/scoreboard.json 由 canonical traces 派生。
最终正确率与证据质量分开审查；服务错误、预算耗尽和弃答不算明确误判。

## 已完成：首轮没有区分 solo 与 debate

四例 × 三组的 12 次实验全部完成，60 个实际 API 请求的原始记录均完整，无传输
失败、预算耗尽或弃答。逐次请求的剩余额度与返回 usage 已核对，所有协议检查通过。

| 组别 | 正确 | 明确误判 | API 估算 |
|---|---:|---:|---:|
| 无工具单次调用 | 3/4 | 1 | $0.011507 |
| Solo＋工具 | 4/4 | 0 | $0.079168 |
| Debate＋工具 | 4/4 | 0 | $0.264906 |

本批 API 估算合计 **$0.355581**，不含 Modal GPU 费用。没有未知 API 用量。
Debate 约为 solo 的 3.35 倍 API 估算费用，尽管总输出额度相同；其输入上下文和
实际调用数量不同。不能将相同输出上限写成相同总成本。

Solo 在 case_62/case_63 自行识别初始参考的共用数值问题，用独立居中 FP64 参考重新
比较真实 GPU 输出；在 case_64/case_65 自行穷举全部 121 个合法操作字。由此纠正了
初始测试的不充分性，不需要另一角色介入。无工具只在 case_64 上误拒正确实现。

所以本轮未触发第二轮或六例扩展：**现在只有四例 pilot，没有批量生产十例**。
这否定了“这两个具体构造已足以区分现有 solo/debate”的试验预期，并不证明所有
任务上两者等价。后续若要换机制或升级 debate，应另开版本，保留此次完整负结果。
