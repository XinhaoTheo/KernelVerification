# 实测结论：找到一对能区分无工具单次调用与带工具验证的候选

本轮只评测事先冻结的两个案例。没有根据模型回答修改输入、kernel、阈值或标签。
独立 GPU 核验、单次调用和四角色 debate 都已执行，原始记录保存在本目录。
所有模型评测使用 `claude-opus-5`；每次模型调用上限为 32768 output tokens。

| 案例 | T4 实测误差 / 10% 要求 | 单次调用原始说明，第 1 / 2 次 | 删除解释句后的单次调用 | 四角色 + 工具 |
| --- | --- | --- | --- | --- |
| case_36 | 22.4116%，不合格 | trust / trust，两次误接受 | reject，正确 | reject，正确 |
| case_37 | 3.3647%，合格 | reject / reject，两次误拒绝 | reject，仍然误拒绝 | trust，正确 |

这里的“删除解释句”仅移除“单路误差可以独自超过 0.1”这句非约束性说明；
最终输出误差要求、阈值、源码、输入均保持不变。这项消融是看到前两轮回答后追加的，
用于检查措辞敏感性，不与原始条件混为一个预注册实验。
全部六次单次调用正常以 end_turn 结束，没有预算耗尽，也没有 needs_more_evidence。

## 为什么 case_37 是较强的结果

case_37 的三次无工具回答均使用独立误差估算，预计最终相对误差约 17%，从而拒绝。
置信度分别为 0.84、0.83、0.86。但 case_37 的行排列是按两路实际量化残差匹配的，
排列之后两路误差并不独立。生成矩阵时使用独立随机抽样，不能推出经过这种排列后
两路误差仍然独立。

Debate 的 t8 probe 直接运行 kernel 并用原始 FP32 输入计算 FP64 reference，
得到 E=0.03364714675。t9 独立分解两路误差，得到：

- 单路误差范数分别约 0.850 和 0.962。
- 独立误差假设预测合并范数约 1.283；真实合并范数约 0.269。
- 实测 Pearson 相关系数约 -0.964，说明抵消是关键。
- t12 又重复执行五次，输出逐位相同，误差距阈值约有 2.97 倍余量。

因此这次存在完整的证据链：无工具回答误用了统计假设，带工具系统测量了目标输出，
进一步检查了错误假设，并给出了正确 verdict。工具没有获得答案文件或构造侧测量。

## case_36 的局限不能省略

case_36 在原始说明下两次被误接受：模型根据“允许单路误差超标”的说明猜测排列是为了抵消。
移除该句后它正确拒绝。因此 case_36 的错误存在明显措辞敏感性，不能宣传为与措辞无关的稳定难例。

case_36 的 debate 正确拒绝，并直接测得 E=0.22411580645，独立量化模拟也复现了这个数。
但 Judge 的解释仍错误地声称两路误差独立、按平方和相加。0.850 和 0.962 的平方和开根
仅约 1.283，不是 probe 记录的 1.790。正确 verdict 有直接实验支撑，机理解释却仍有错。
自动 trace 审计未发现流程错误，不能因此宣称所有自然语言解释都正确。

## 能与不能证明的内容

这是两个精心构造的固定 workload，不是原有全输入域 kernel 正确性问题，也不是对独立
大样本的统计结论。两份代码只改变排列常量，单路数据与误差范数一致，最终标签相反。
完整输入生成代码对无工具与带工具系统都公开，但计算访问权限不同。

这证明至少有一个经过实测的“无工具单次调用误判、带工具 debate 能解决”的候选。
它不证明强模型理论上无法静态求解、不证明换模型或提示后仍必然失败，也不证明
四角色优于同模型单 agent + tools。补测的 case_37 单 agent + tools 对照也正确返回 trust，
使用独立 FP64 reference 测得同样的 3.3647%，并重复五次确认。因此这个结果支持的是
执行工具的价值，尚不支持四角色结构的额外价值。

正确 reference 与指标都已给出，因此一个按要求运行的固定数值检查脚本也能解决。
不要将这一结果解释成击败所有 allclose 检查，或直接并入原有 FN/FP scoreboard。
