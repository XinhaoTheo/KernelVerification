Operation: fused cross-entropy forward with predicted-token reporting
(linkedin/Liger-Kernel, src/liger_kernel/ops/cross_entropy.py::liger_cross_entropy_kernel).

`cross_entropy_with_predictions(logits, target)` returns

    loss[i]      = -log softmax(logits[i])[target[i]]
    predicted[i] = argmax over j of logits[i, j]

The logits row is scanned in blocks, so the argmax is accumulated across blocks
rather than computed in one shot.

Tie rule: when several vocabulary entries attain the row maximum, `predicted`
must be the LOWEST such index. Downstream decoding gathers an embedding row for
the predicted token, so which of the tied entries is reported changes the
continuous output that follows.

Input domain: `n_cols` is the vocabulary size and may exceed the kernel's block
size, in which case a row spans several blocks and a tie may fall in different
blocks.

Does cross_entropy_with_predictions() satisfy this contract?
